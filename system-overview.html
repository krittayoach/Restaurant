QR Code System

🏪 Manager สร้าง QR
1

เปิดหน้า QR Dashboard

/dashboard/{slug}/tables/qr

2

กด "สร้าง QR" หรือ "สร้างทุกโต๊ะ"

ระบบสร้าง qrToken = randomBytes(32).hex() บันทึกลง PostgreSQL

3

Download PNG หรือ Print Sheet

ได้ QR image พร้อมชื่อร้าน + โต๊ะ นำไปวางบนโต๊ะได้เลย

4

Reset ได้ทุกเมื่อ

Token เก่าจะหมดอายุทันที ป้องกัน QR เก่าถูกใช้

👤 ลูกค้าแสกน QR
1

แสกน QR บนโต๊ะ

เปิด app.domain.com/r/{slug}/table/{qrToken}

2

Server Resolve Token

GET /tables/resolve/{qrToken}?slug={slug}
ตรวจ slug ตรงกันป้องกัน token ข้ามร้าน

3

Set Cookie + Load Menu

เก็บ tableId, restaurantId ใน httpOnly cookie · โหลดเมนูจาก Redis cache

4

พร้อมสั่งอาหารทันที

ลูกค้าเห็นเมนูของร้านนั้น context โต๊ะถูก preset แล้ว

Kitchen & Serving Flow

👨‍🍳 Kitchen Board (พ่อครัว)
SSE Stream ออเดอร์ใหม่ปรากฏทันทีไม่ต้อง refresh · Pub/Sub ต่อ restaurantId
Card View แสดงเวลาที่สั่ง · ไฮไลท์แดงถ้าเกิน 15 นาที · แสดงหมายเหตุลูกค้า
Actions รับทำทีละ item หรือ "รับทั้งออเดอร์" · บันทึก startedAt/finishedAt
Stats จำนวน pending/cooking/ready · เวลาเฉลี่ยต่อ item วันนี้
🧑‍🍳 Floor View (พนักงาน)
Floor Map ผังโต๊ะพร้อมสถานะ · pending/cooking items · สีบ่งบอกสถานะ
Ready Panel รายการพร้อมเสิร์ฟแยกชัดเจน · SSE แจ้งเมื่อครัวทำเสร็จ
Actions เสิร์ฟทีละ item หรือทั้งออเดอร์ · เพิ่มรายการเข้า order เดิม · ยกเลิก pending
Payment ยืนยันสลิปโอน · รับชำระสด · คืนเงิน · โต๊ะ reset เป็น available อัตโนมัติ

Order Item Status Flow

pending
ลูกค้าสั่ง
→
cooking
พ่อครัวรับทำ
→
ready
ทำเสร็จ → SSE
→
served
พนักงานเสิร์ฟ
│
cancelled
ยกเลิก (pending เท่านั้น)
Order-level sync
Order status ถูก sync อัตโนมัติจาก items — ถ้าทุก item served → order served, ถ้าทุก item ready → order ready
Timestamps
บันทึก startedAt เมื่อ cooking, finishedAt เมื่อ ready, servedAt เมื่อ served — ใช้คำนวณเวลาเฉลี่ยครัว
Cancel Guard
ยกเลิก item ได้เฉพาะ pending — ถ้า cooking ขึ้นไปแล้วต้องติดต่อพนักงาน และ recalculate total อัตโนมัติ

Redis Key Patterns

session:{token}
JWT session payload ของ staff ทุก role
TTL 24h String
cache:{restaurantId}:menus
เมนูทั้งหมดของร้าน (เฉพาะที่เปิดขาย) ถูก invalidate เมื่อ CRUD เมนู/category
TTL 5 min JSON String
{restaurantId}:order:active:{tableId}
orderId ที่ active ของโต๊ะนั้น ลบเมื่อชำระเงินเสร็จ
No TTL String
{restaurantId}:queue:kitchen
Kitchen order queue (lpush เมื่อสั่ง)
No TTL List
{restaurantId}:kitchen (Pub/Sub)
SSE channel ครัว → NEW_ORDER, ITEM_STATUS, ORDER_ACCEPTED
Pub/Sub Realtime
{restaurantId}:order:update (Pub/Sub)
SSE channel พนักงาน → ITEM_READY, ITEM_SERVED, ORDER_SERVED
Pub/Sub Realtime
ratelimit:login:{ip}
นับครั้ง login fail ต่อ IP ป้องกัน brute-force
TTL 5 min Counter
{restaurantId}:table:{tableId}:status
สถานะโต๊ะใน memory สำหรับ floor view (sync กับ PostgreSQL)
No TTL String
